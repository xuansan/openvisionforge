本次审查对象：Rust runtime 当前实际注册的全部节点。

审查命令：


结果：

- `cargo test` 通过。
- 13 个示例 workflow 全部跑通。
- schema 导出正常。
- 结论：不是所有节点都等价于“生产可用”。当前应分为真实可用、mock 可用、outbox/manifest 可用、接口占位、外部依赖可用几类。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 可用 | 本地可运行，当前实现能完成该节点主要功能。 |
| Mock 可用 | 可运行，但明确是模拟数据或模拟设备。 |
| Outbox 可用 | 可运行，但只写 outbox/manifest 文件，不是真实连接外部系统。 |
| 外部依赖 | 节点逻辑存在，但真实使用依赖模型、DLL、API key、服务端或硬件。 |
| 接口占位 | 节点已注册，能参与 UI/schema/workflow，但算法或真实后端尚未实现完整能力。 |

## 总体结论

| 模块 | 结论 |
| --- | --- |
| OpenCV 图像读写、阈值、滤波、增强、形态学、边缘、变换 | 基本可用。 |
| OpenCV 轮廓/Blob/部分缺陷 | 部分可用，部分是简化或预留。 |
| OpenCV 定位 | 目前主要是接口占位，不是真实模板匹配/特征匹配。 |
| OpenCV 几何测量 | 可用，但不少是基于参数或轮廓统计的 MVP 测量，不是完整工业测量算法。 |
| 可视化叠加 | 基本可用；`draw.contours` 当前画 bbox/中心点，不是真实轮廓 polyline。 |
| YOLO detect | 在 mock 后端可运行；真实 ONNX 依赖模型和 ONNX Runtime。 |
| Ultralytics segment/classify/pose/obb | 已注册但明确预留，调用会报 not implemented。 |
| Qwen VLM | 当前是 API 请求准备节点，不会真实请求 Qwen API。 |
| 通信节点 | 默认 outbox 可用；真实 HTTP/Webhook 可用但依赖网络；Kafka/MQTT 等没有真实 SDK 发送。 |
| 数据库节点 | 全部 outbox 可用，不是真实数据库读写。 |
| 存储上传 | local/NAS 可本地写；RustFS/S3/OSS 是 manifest，不是真实上传。 |
| Action/PLC/Robot/Alarm | outbox 可用，不是真实硬件控制。 |

## 需要优先修正的点

1. **UI 里应标记节点成熟度**：`可用 / mock / outbox / 预留 / 外部依赖`，否则用户会以为所有节点都生产可用。
2. **定位节点需要真实算法替换**：模板匹配、旋转模板、多尺度模板、特征匹配、圆/线/角点定位当前是最大误导风险。
3. **Ultralytics 非 detect 节点需要隐藏或标预留**：segment/classify/pose/obb 当前调用会失败。
4. **数据库/消息队列/对象存储需要明确 outbox 语义**：现在不是 SDK 真连接。
5. **Qwen VLM 节点要么改名为 prepare，要么接真实 API 调用**：当前不会请求模型。
6. **Draw contours 需要后续保存完整轮廓点集**：否则只能画 bbox，不是真轮廓。
