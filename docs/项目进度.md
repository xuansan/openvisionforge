更新时间：2026-10-28

本文档用于记录 OpenVisionForge 当前已经完成的内容、正在推进的内容、下一步计划和后续维护规则。之后每次修改代码、调整架构、补充节点或更新 UI 时，都需要同步更新本文档。

## 1. 项目定位

OpenVisionForge 是一套面向工业视觉检测的开源平台底座。

核心目标不是单纯做一个拖拽式 UI，而是建立一个 Rust-first 的工业视觉检测框架：

- 使用 Rust 作为核心执行、校验、流程调度和部署运行基础。
- 使用 React / Tauri 作为开发、调试和流程编排 UI。
- 使用节点化方式封装图像输入、OpenCV 算子、深度学习推理、逻辑判断、结果输出、存储和通信能力。
- 工作流通过 JSON 表达，UI 负责编辑，Rust runtime 负责最终校验和执行。
- 后期支持按需构建、轻量部署、插件化或模块化扩展。

### 3.13 阶段 6 已完成内容

阶段 6 MVP 定义为“工业检测结果闭环”，目前已完成：

- 工作流新增可选 `metadata`，用于保存产品、批次、模型和标定版本等追溯信息。
- 节点新增强类型执行策略：
  - `run_when`：`always`、`all_ok`、`any_ok`、`all_ng`、`any_ng`。
  - `always_run`：短路后仍执行最终汇总、记录和输出节点。
  - `short_circuit_on_ng`：关键节点输出 NG 时触发后续短路。
- runtime 支持 `skipped:condition_not_met`、`skipped:short_circuit` 和 `skipped:upstream_skipped` trace 状态。
- Rust 校验会拒绝没有规则/布尔/最终结果输入的条件执行节点，以及没有判定输出却配置短路的节点。
- 保留 `logic.and`、`logic.or` 兼容节点，并新增更明确的 `logic.all`、`logic.any`、`logic.n_of_m`。
- `logic.n_of_m` 支持配置至少通过 N 条规则。
- `logic.final_result` 继续作为最终 OK/NG 汇总权威，输出 `FinalResult`、状态文本和布尔结果。
- runtime 每次执行自动生成 `inspection_result.json`，包含 workflow 元数据、最终结果、节点 trace、耗时和全部节点输出。
- 节点失败时仍会保存 `trace.json`、`event.json` 和 `inspection_result.json`；普通异常标记为 `ERROR`，包含 timeout 语义的后端错误标记为 `TIMEOUT`。
- `record.result.json` 升级为标准检测结果节点，支持产品、批次、模型和标定版本，输出可继续进入通信或数据库节点的 `result`。
- Webhook、WebSocket、HTTP、MQ 以及数据库写入节点可以直接消费标准 `result` 或 `final`。
- UI 节点实例面板新增执行条件、短路后仍执行、NG 时触发短路配置，保存到同一个 workflow JSON。
- 新增并实跑：
  - `phase6_inspection_ok_demo.json`：输出 `OK`。
  - `phase6_inspection_ng_demo.json`：输出 `NG`。
  - `phase6_short_circuit_demo.json`：条件分支被记录为 `skipped:short_circuit`，最终汇总和结果记录仍执行。
- OK/NG Demo 均生成标注图、标准结果 JSON、运行 trace 和 Webhook outbox。
- 新增执行器单元测试，覆盖条件跳过、短路、`always_run` 和异常结果落盘。

阶段 6 的限制：

- 当前 `TIMEOUT` 能记录后端明确返回的超时错误，但 Rust 进程内算子还不能被安全强制中止；硬超时需要后续子进程/插件执行隔离。
- Kafka、数据库等部分节点仍是 outbox/manifest 实现，真实 SDK 投递与后台重试 worker 尚未全部完成。
- 当前短路作用于一次单帧 DAG 执行；批次和视频流的跨帧状态机留到后续阶段。

阶段 6 复查修复：

- `record.result.json` 的 `final` 恢复为可选输入，修复旧推理、IO 和质量检测示例无法运行的兼容性回归。
- `record.result.json` 在没有 `final` 时继续保存普通算法结果并使用 `UNKNOWN`，有 `status` 文本时保留该状态。
- `Executor::run` 现在同时调用统一的 `validate_workflow`，CLI 与 UI 共用参数、端口类型和执行策略规则。
- 算子缺少 Schema 声明的必需输出时，也会保存 `ERROR` 的 trace、event 和 inspection result。
- 工作流限制最多一个 `logic.final_result`，runtime 优先读取该节点的强类型 `FinalResult`，不再按节点 ID 顺序误取中间状态。
- Webhook、数据库等外部输出会直接发送标准 JSON 内容，不再把 `Value::Json` 的 `kind/data` 内部包装作为 payload。
- Webhook 的 `url` 改为可选，允许只配置 `url_env`，与实际运行逻辑保持一致。
